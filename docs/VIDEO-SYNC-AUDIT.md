# Video sync audit — narration vs picture

*Started Sep 12 2026. A parent watching the lesson videos reported that the narration and the picture sometimes drift apart.*

## How sync works today

- A lesson video is a sequence of scenes. Each scene's length is derived from its narration clip: `max(minimum, clip + 0.8 s)` (`earlyTimings` in `src/remotion/lesson/timeline.ts`). The clip starts exactly when the scene starts (`<Audio>` inside the scene's `<Sequence>`). **Scene-level sync is therefore correct by construction.**
- The voice manifest (`src/remotion/lesson/voice-manifest.ts`, generated by `scripts/build-lesson-voice.ts`) stores each clip's duration and `numberTimes`: the second at which the narrator says each number, from ElevenLabs word alignment. 625 of 675 clips have it; 50 clips across 46 units were narrated without alignment.
- **Inside a scene, no template uses `numberTimes`.** Every reveal fires at a hand-picked frame — `firstAt = 16`, `secondAt = Math.round(dur * 0.52)`, `appearAt = firstAt + i * 4` — while the narrator reaches that number at whatever second the recording landed on. Across the 26 templates there are ~430 such reveal sites. This is the systematic cause of the drift a viewer notices: the picture is early or late by however far the guess missed.

## What the audit checks

1. `scripts/audit-video-sync.ts <outDir>` — machine-provable facts for all 168 videos: manifest duration vs the real mp3, clip longer than its scene (narration cut off), script numbers absent from the recording (line changed after narration), rendered mp4 length vs the timeline (stale render), scenes without word alignment. It also lists, for every scene, the second at which each number is spoken.
2. `scripts/render-sync-stills.ts <outDir> [units]` — renders the frame 0.25 s after each spoken number (and one at the end of each clip) so a reviewer sees exactly what a viewer sees while hearing the number. `index.md` says what each still should show.
3. Reviewer pass over the stills: present / late / early / absent per still.

## The fix (engine-level, so it holds for every video)

1. Pass the scene's clip (with `numberTimes`) into every scene body via `SceneProps`, and add a helper `saidAt(clip, n, occurrence, fallbackFrame)` in `timeline.ts` that returns the frame the narrator says `n`, falling back to the hand-picked frame when the clip has no alignment.
2. Convert number-bound reveals in each template from fixed frames to `saidAt(...)`. Reveals that are not bound to a spoken number (titles, transitions) keep their frames.
3. Re-narrate the 50 unaligned clips with alignment (`scripts/build-lesson-voice.ts <unit …>`) so those scenes can sync too.
4. Gate: extend `scripts/validate-videos.ts` so a scene whose clip has alignment must place each number-bound reveal within ±0.4 s of the spoken moment (the template reports its reveal frames through the same helper).
5. Re-render every affected video, run `npm run audit:videos`, upload, then re-export `Desktop\eduyro-lesson-videos`.
